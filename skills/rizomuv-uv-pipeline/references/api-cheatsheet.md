## Launching and closing

| Call | Notes |
|---|---|
| `sys.path.insert(0, "<install>/RizomUVLink"); from RizomUVLink import CRizomUVLink, CZEx` | The package picks the compiled module for the running Python (3.6-3.13 on Windows; 3.9-3.13 on Linux/macOS). Python 3.14 has no build yet. |
| `link = CRizomUVLink(); port = link.RunRizomUV(exePath=..., headless=True)` | Picks the first port in 49152-65534 with nothing listening, launches `rizomuv.exe -id <port> -hl` and waits until it answers. **Unsafe for parallel work**: the launch is serialised by a per-port lock file in `%TEMP%`, and a second launcher that loses that lock *waits for and connects to the first launcher's instance*. Two clients on one port then swap replies (measured: a cube came back as another job's icosphere, with no error). `rizom_link.RizomSession` avoids it (see "Running several instances"). |
| `subprocess.Popen([exe, "-id", str(port), "-hl"])`, then `link.Connect(port)` | What `rizom_link` does: its own process on a port it has locked, so it can verify, prioritise and kill exactly that instance. About 2-3 s alone, 5-9 s with three starting together; the first launch after install can take much longer (antivirus), hence the 120 s default timeout. |
| `headless=True` / `-hl` | Needs 2027.0.417+; an older build shows a usage box nobody can dismiss and never opens its port (README). `rizom_link` reads the executable's file version (2027.0.598) and refuses older builds before launching. No window and no dialogs: what a dialog would have said goes to the command log, answered "no". Still needs a logged-in desktop session (Windows) or an X display (Linux); it will not run as a service or in a bare container. |
| `background=True` / `iconized=True` | Window behind the host (2027.0.297+) / minimised. Use when the user may want to look. |
| `link.Quit({})` | Always in a `finally:`. A headless instance has no window to close, so a script that forgets leaves an invisible process (and on a floating licence, a token) behind. `Quit` returns before the process has exited: wait on the process (`RizomSession.close` waits, then kills after 10 s). |
| `link.RizomUVVersion()` | String such as `2027.0.598.g864535413`; log it with every result. |
| `link.Connect(port)` | Attach to an instance started with `rizomuv.exe -id <port>`. The instance also binds `port + 1` (change notifications), so give instances ports two apart. |

Locating the install: Windows registers each version under `HKLM\SOFTWARE\Rizom Lab\RizomUV VS RS <major>.<minor>`
(the default value of the subkey `rizomuv.exe` is the executable path **without** `.exe`, measured on 2027.0: add
it), and `rizomuv.exe` carries its version as the file version. macOS: `/Applications/RizomUV.<ver>.app`, package at
`Contents/Resources/RizomUVLink`. Linux: the package is inside the AppImage at `usr/bin/RizomUVLink`, and the
launchable entry of an extracted AppImage is the AppDir's `AppRun` (the bare `usr/bin/rizomuv` has no rpath):
set `RIZOMUV_EXE` to `AppRun`. `scripts/rizom_link.py` does all of this, with `RIZOMUV_EXE` / `RIZOMUVLINK_DIR`
overrides.

**The temp folder must be short** (measured 17 Oct 2026). libzmq 4.3.4, inside both RizomUV and RizomUVLink, puts
a socket file under the temp folder; with a temp path of 115 characters RizomUV exited at start (code 0x40000015)
and the client process aborted, in `Connect` (`Bad file descriptor ... epoll.cpp`) or when the link object was
collected (`Assertion failed: Socket operation on non-socket ... signaler.cpp`); 79 characters worked. The client
reads the temp folder when the link object is created: creating it under a short folder is enough, Connect and
every command may then run under the long one. `rizom_link` hands RizomUV and the link object a short folder
(`%LOCALAPPDATA%\Temp`) when the current one is longer than 90 characters.

## Fileless data transfer

```python
link.Load({"Data.PolySizes": sizes,        # corners per polygon
           "Data.PolyXYZIDs": xyz_ids,     # 3D vertex per corner
           "Data.CoordsXYZ": xyz,          # flat x,y,z
           "Data.PolyUVWIDs": uvw_ids,     # UV vertex per corner: splitting a vertex here IS a seam
           "Data.CoordsUVW": uvw})         # flat u,v,w seed
d = link.Save({"Data": True})["Data"]      # d["PolyUVWIDs"], d["CoordsUVW"] (and d["PolySizes"])
```

- Polygon and corner order are preserved: write `d["PolyUVWIDs"]` back corner by corner. The UV vertex count
  changes (cuts add vertices), the corner count does not.
- **Seed the UVs with the 3D positions**, not zeros: Unfold sizes islands from the seed area (FilelessMeshTransfer.py
  says the same).
- **Seams travel in the seed topology.** Give two corners different `uvw_ids` and that edge is cut before RizomUV
  starts; `Select Auto` then adds its own cuts. This is how generator seams and Blender `use_seam` edges get in.
- `Save({"IndexTable.PolygonIDsToIslandIDs": True})["IndexTable"]["PolygonIDsToIslandIDs"]` gives the island
  of each polygon. Ask for it in its own call: combined with `"Data": True`, only the index table comes back.
- `"Data.UseImportedUVWPolygons": True` on Save keeps the imported UV vertex numbering when RizomUV had to repair
  topology and the host cannot take topology changes.
- Load replaces the current mesh, so one instance can process a whole batch.

## The commands this pipeline uses

```python
# 1. auto seams (on top of the seed seams), cut, clear the selection
link.Select({"PrimType": "Edge", "WorkingSet": "Visible", "Select": True, "ResetBefore": True, "Auto": {...}})
link.Cut({"PrimType": "Edge", "WorkingSet": "Visible"})
link.Select({"PrimType": "Edge", "WorkingSet": "Visible", "DeSelect": True, "All": True})
# 2. flatten
link.Unfold({"PrimType": "Island", "WorkingSet": "Visible", "BorderIntersections": True, "TriangleFlips": True,
             "Iterations": 5})
link.Optimize({"PrimType": "Island", "WorkingSet": "Visible", "BorderIntersections": True, "TriangleFlips": True,
               "Iterations": 25, "Mix": 1.0, "AngleDistanceMix": 1.0})
# 3. pack (see below), then Save
link.IslandGroups({"Mode": "DistributeInTilesEvenly", "WorkingSet": "Visible"})   # required after a fileless Load
link.Pack({...})
```

`Auto` keys (the GUI name in brackets): `SharpEdges.AngleMin`, `PipesCutter` (Link holes), `HandleCutter`
(Cut handles), `QuadLoopCutter`, `QuasiDevelopable` (Mosaic: `Developability`, `IslandPolyNBMin`, `AreaMinRatio`,
`FitCones`, `Straighten`, `IslandsNB`), `Skeleton` (Hierarchical: `Open`, `SegLevels`), `Box`, `StretchLimiter`,
`Quality` (the stretch limiter's threshold, 0-1), `FlatteningMode`, `SizeLimiter.LengthRatio`, `ReWeld`
(`Threshold`, `PolyMax`, `LENGTHMax`), `Smooth` (`Iterations`, `Force`), `SkeletonUnoverlap`, `BooleanUnoverlap`.
What each does to distortion: `distortion-and-quality.md`. Integers are accepted where a double is expected
(measured: `"Mix": 1` and `1.0` both work).

Other commands worth knowing: `Weld`, `Hide`, `Tag`, `IslandProperties`, `RasterExport` (layout and stretch
images), `Uvset` (multiple UV sets), `GenerateCheckerboardTexture`. In 2027, `Unfold` and `Optimize` also take
`AlignBorders` (straighten island borders to U and V), not used by these scripts yet.

`Hotspot` matches islands to trim-sheet rectangles (`Match.Tags`/`Match.Materials`; the trims come from
`IslandGroups` `ImportTrims`, an SVG). This skill does not automate it: it is used interactively in RizomUV, and trim
matching in this repo is done by hand following the `uv-unwrapping` skill.

## Pack: scaling, layout and the undocumented parts

```python
link.Pack({"RootGroup": "RootGroup", "WorkingSet": "Visible", "ProcessTileSelection": False,
           "RecursionDepth": 1,              # pack the tiles' contents (0 would pack only the tiles: nothing)
           "Translate": True, "UsePixelUnit": True, "PaddingSizePx": 16, "MarginSizePx": 8,
           "MapResolution": 1024, "Strategy": "PaddingPerfect",   # or "Efficient" (the default), "PixelAligned"
           "Rotate": {"Step": 90.0},         # smaller steps cost time; directional textures: see Rotate.Initial below
           "Device": "CPU",                  # default "FastestGPU" (CUDA, falls back to CPU)
           "Scaling": {"Mode": 2},           # nested dicts and dotted keys ("Scaling.Mode") are equivalent
           "LayoutScalingMode": 2})
```

The enum names are documented, their integers are not. Measured (re-check with `scripts/probe_pack_enums.py`
after an upgrade): 0-based in the documented order.

| `Scaling.Mode` | Name | Behaviour seen |
|---|---|---|
| 0 | OFF | islands keep their size |
| 1 | SET_3D_AREA | UV area = 3D area (ratio 1) |
| 2-5 | AVG_RATIO_OF_MOVABLE / GROUP / FIXED / ALL | one shared ratio, the area-weighted average (identical when every island is movable in one group) |
| 6 | AVG_RATIO_USER_SPECIFIED | ratio = `Scaling.SpecifiedScale` exactly |
| 7 | TEXEL_DENSITY | ratio = `Scaling.TexelDensity` / (100 x `MapResolution`): see below |
| 8 | PIXEL | average edge = one pixel |
| 9 | MAP | internal; the command crashes ("bad function call") |

| `LayoutScalingMode` | Name | Use |
|---|---|---|
| 0 | DISABLED | leave everything where packing put it |
| 1 | TRANSLATE_ONLY | texel-density packs (no rescale afterwards) |
| 2 | BEST_FIT | fill the tile uniformly: per-piece maps and lightmaps. Keeps the margin (measured: layout 0.004-0.996 at margin 4 px of 1024) |
| 3 | FORCE_FIT | non-uniform fill: distorts, avoid |

Behaviour that differs from, or is missing in, the docstrings:

1. **`Scaling.Optimization` defaults to `"Fill"`** (in GitHub's 2027.0.737 docstring; the copy shipped with
   2027.0.598 lists no default): `Scaling.Mode` sets the islands' relative sizes, then the whole layout is scaled
   to fill the tile. Any absolute request (modes 1, 6, 7) is lost. Pass `"Optimization": "None"` inside
   `Scaling` for them. It works in the top-level Pack call (measured), although the docstring says it "can only
   placed in the RootGroup".
2. **`TexelDensity` is per 100 mesh units.** The docstring says the unit comes from `Scene.Setting.Unit` (and
   `Load` has a `DefaultUnit` for files); for fileless meshes RizomUV treats the coordinates as centimetres, so
   metre input needs `TD x 100`. Use mode 6 with `SpecifiedScale = px_per_unit / MapResolution` instead: exact, in
   whatever unit the mesh is in (the docstring's own formula: `SpecifiedScale = TD x tileSize / mapRez`).
3. **A scale that cannot fit leaves the islands untouched**: no error, same return value (the docstring says the
   box is grown). Always measure the result (`rizom_uv.pack` returns `fits`).
4. **After a fileless Load, `Pack` packs only what lies in the 0-1 tile.** Measured 17 Oct 2026 on a box: seeds
   inside 0-1 were packed; seeds spanning 0-2.4 were only partly packed (V fitted, U left at 2.4); seeds at 5-5.8,
   or straddling 0 (-0.5 to 0.3), were left untouched. World-space seeds (metres) are rarely all inside the tile,
   so call `IslandGroups({"Mode": "DistributeInTilesEvenly"})` first: it put every case in the tile.
   `NormalizeUVW` on Load does not help.
5. **`Coverages` comes back empty** in fileless mode (`{"Coverages": []}`): measure coverage yourself
   (`uv_metrics.report`).
6. A top-level `"Global"` parameter is rejected (`The parameter 'Global' is not recognized`), although the
   docstring describes one. Per-island or per-group values go through `IslandProperties` / `IslandGroups`.
7. `Device` defaults to `"FastestGPU"` (documented). This skill passes `"CPU"`: it leaves the GPU to bakes and
   anything else running. CPU and GPU packs have not been compared; pass `device="FastestGPU"` to `pack_spec` for
   very large batches if the GPU is free.
8. Not every unwrap is repeatable: the same organic mesh came back with 76-79 islands across calls and processes
   (Suzanne), while simpler meshes were bit-identical. Compare grades with tolerances, never hashes.
9. **`Rotate.Step` 0 alone does not keep a direction**: each island keeps whatever orientation the unfold gave it
   (measured 17 Oct 2026 on a plank crate: 37 grain faces along U, 39 along V). Pre-orient with `Rotate.Initial`
   and keep it with `Step` 0. Values (docstring): `"Off"`, `"Auto"`, `"Horizontal"`, `"Vertical"`, or an axis map
   `"Main3D|MainUV|Backup3D|BackupUV"`. Measured: `"Horizontal"` laid all 76 grain faces along U (each island's
   long side; coverage 0.573 against 0.561), `"Vertical"` all along V, `"Z|+V|X|+U"` turned world up to +V on a
   sign's vertical faces. `rizom_uv.directional()` sets them (`"grain"`, `"upright"`); `probe_pack_enums.py`
   re-checks Horizontal and Vertical.
10. **The gap has a ceiling with many islands**: PaddingPerfect's closest gap tops out near map_px / (2 x
   sqrt(islands)) whatever the asked padding, map size, texel-density scaling or `Resolution` (measured 17 Oct 2026:
   1500 islands, 16 / 32 / 64 px asked at 1024 / 2048 / 4096 gave 13.0 / 27.0 / 54.1 px). Above about 1000 islands
   the map/64 gap cannot be met at any size: fewer islands, or another texture set.

## Stretch maps

`RasterExport` with `PolygonColorMode "Stretches"` grades **linear** scale (UV length / 3D length), although its
docstring says "triangle area ratio": measured 17 Oct 2026, the urn's layout came out grey with Neutral = sqrt(UV
area / 3D area) = 0.293 and saturated blue with the area ratio 0.086. Set Neutral to the layout's mean linear ratio
and Min / Max at neutral / 1.25 and x 1.25 (`rizom_uv.stretch_map`); the default Neutral of 1.0 gives one flat
colour. `probe_pack_enums.py` re-checks it.

## Reading state

- `link.Count("Lib.Mesh.Islands")` works (a dotted path string, not a dict).
- `link.Get("Lib.Mesh.RootGroup.Children")` and other group trees fail to serialise (`CSubMeshGroup`): read the
  data with `Save({"Data": True})` instead.
- `link.GetVersion("Lib.Mesh.UVW")` returns a change token without transferring data (for live bridges).

## Errors

- A failed `Load` **returns** `{"Error": {"Msg", "Code"}}` instead of raising (examples/Headless.py). Check it, or
  the failure surfaces several commands later as something unrelated.
- A command that fails inside RizomUV raises `CZEx`. A lost connection (crash) also raises rather than hanging:
  measured 17 Oct 2026, a killed instance raised `RizomUV is not responding ... Duration = 2001ms for a timeOut:
  2000ms` on the next command.
- Paths passed to RizomUV (`RasterExport`, file Load/Save) must be absolute with forward slashes, in a folder that
  exists: RizomUV's working directory is its install folder, and with a relative path or a missing folder it writes
  **nothing** and reports no error. Check the file afterwards.
- A headless instance that cannot start (no licence, an unknown flag) exits before opening its port; what it would
  have shown is at the end of its command log, `<Documents>/RizomUV/<major>/logs/CommandLog.py`.

## Running several instances

The link protocol is one client per port, and nothing in RizomUVLink stops two clients sharing one: replies then
cross silently. Rules that held under test (3 processes launched in the same millisecond, 3 threads):

1. **One private instance per session.** Claim the port with an OS file lock held for the whole session (released
   by the OS if the holder dies), check nothing listens on it or on `port + 1` and both can be bound (a reserved
   or half-used port fails the bind), start `rizomuv.exe -id <port> -hl` yourself, wait for the port, then check
   that the process listening is your child (Windows: `GetExtendedTcpTable`). `rizom_link.RizomSession` does this,
   on ports 61000-64998 (above `RunRizomUV`'s scan).
2. **Separate processes for parallel work** (`rizom_pool.py`). Threads with their own sessions also measured
   clean, but never share one link between threads.
3. **Tie the instance to its host.** On Windows, a Job Object with `KILL_ON_JOB_CLOSE` kills the instance when the
   host dies (measured: gone within 2 s of the host being killed); elsewhere a watchdog process does it. The pool
   ties its workers to the host the same way (measured 17 Oct 2026: killing the host left no worker and no
   RizomUV running).
4. **Restart after a `CZEx` or a timeout** rather than reusing the instance. A killed instance is detected in about 2
   s (`RizomUV is not responding`). **A call holds the GIL for its whole length**, so no thread in the host can time
   it out: a 2 s `threading.Timer` fired only when a 158 s auto-seam returned (a busy machine, 17 Oct 2026). Enforce a
   per-job timeout from a separate process that kills the instance; the blocked call then raises about 2 s later.
   `RizomSession.deadline()` does this (about 50 ms per call to start the helper); measured, an 8 s timeout on an
   82k-face auto-seam failed after 10.1 s (the timer version: 78.5 s), and the batch carried on.

Each instance takes a licence token on a floating licence. A pool of 3-4 is plenty: a 400-face piece takes about
0.3 s to unwrap and pack twice, so launch cost dominates small batches.

## Traps when writing your own calls

The scripts already handle all of these:

| Symptom | Cause | Fix |
|---|---|---|
| `Pack` does nothing; UVs come back at 3D scale | after a fileless `Load` the islands are in no tile | `IslandGroups({"Mode": "DistributeInTilesEvenly", "WorkingSet": "Visible"})` before every `Pack` |
| `Scaling.Mode`, `SpecifiedScale` or `TexelDensity` ignored | `Scaling.Optimization` defaults to `"Fill"` | `"Scaling": {..., "Optimization": "None"}` and `LayoutScalingMode` 1 |
| Texel density 100x too small | `TexelDensity` is read per 100 mesh units | `Scaling.Mode` 6 with `SpecifiedScale = px_per_unit / map_px` |
| Islands unchanged after a texel-density pack, no error | the density does not fit in the tile | measure the result; `ru.pack` returns `fits` |
| Stretch map is one flat colour | default neutral; RizomUV grades **linear** scale | neutral = `sqrt(UV area / 3D area)` of the layout (`ru.stretch_map`) |
| A file RizomUV should write is missing, no error | relative path (its working directory is its install folder) or missing folder | absolute path, folder created, file checked afterwards |
| Confusing failure several commands after a load | `Load` returned `{"Error": ...}` instead of raising | check it (`ru.load` does) |
| `The parameter 'Global' is not recognized` | documented but rejected at the top level of `Pack` | put values in `Scaling`/`Rotate`, or per island with `IslandProperties` |
| `Get` on group trees throws (`CSubMeshGroup`) | the tree does not serialise | `Count("Lib.Mesh.Islands")`, `Save({"Data": True})` |
| `Pack` returns empty `Coverages` | fileless mode | measure coverage yourself (`uv_metrics.report`) |
| `Pack` competes with a bake or a game for the GPU | `Device` defaults to `"FastestGPU"` | `"Device": "CPU"` (the `pack_spec` default) |
| Invisible `rizomuv.exe` processes pile up | a script exited without `Quit`, or its host was killed | `rizom_session()`: closes in `finally:`, and a Job Object (Windows) or a watchdog kills the instance with its host |
| The host aborts in `Connect` with a libzmq assertion | the temp folder is too long | create the link object with TMP/TEMP pointing at a short folder (`rizom_link` does) |
| Grain or text turned 90 deg on some islands | `Rotate.Step` 0 keeps the unfold's orientation, whatever it is | `"Rotate": {"Step": 0, "Initial": "Horizontal"}` (or an axis map such as `"Z\|+V\|X\|+U"`) |
| A timeout fires only when the long call returns | the call holds the GIL, so a timer thread cannot run | kill the instance from another process (`RizomSession.deadline()`) |
